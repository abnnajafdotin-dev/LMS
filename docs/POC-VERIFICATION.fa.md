# نتیجه بررسی PoC

## بررسی ضبط MVP — 2026-11-11

رفع خروجی صفر بایت: پس از تغییر دانلود از Blob به فایل HTTP ذخیره‌شده روی سرور، اجرای کامل Smoke مجدداً با exit code صفر تمام شد. فایل دانلود واقعی Chrome روی دیسک بایت‌به‌بایت با خروجی ضبط مقایسه و برابر بود؛ ضبط بدون میکروفون/دوربین هم فایل غیرخالی تولید کرد. آپلود خالی رد می‌شود و اندازه و امضای WebM قبل از ارائه لینک کنترل می‌شوند.

Build با صفر خطا و هشدار و اجرای کامل Smoke با exit code صفر تأیید شد. ضبط مرورگری WebM با ابعاد 1280×720 تولید و مجدداً در Chrome پخش شد؛ صدای فایل نیز decode شد و نمونه‌های غیرصامت داشت. اتصال میکروفون مدرس و فراگیر به میکسر، اعلان ضبط برای فراگیر، رد تغییر وضعیت توسط فراگیر و کاربر بدون نشست، و نبود متن چت در رندر اختصاصی بررسی شدند. جابه‌جایی اشتراک صفحه/تخته در طول ضبط تست شد. فایل نمونه `.run/demo-recording.webm` و تصویر پخش `.run/demo-recording-playback.png` هستند. رسانهٔ آزمون مصنوعی است. جزئیات و محدودیت‌ها در [راهنمای ضبط](RECORDING-MVP.fa.md) آمده‌اند.

تاریخ: 2026-11-11 — اجرای محلی Windows x64

## نتیجه نهایی

Build بک‌اند با SDK محلی 10.0.404 موفق شد: **صفر خطا، صفر هشدار**. سرور رسمی LiveKit 1.13.11 و ASP.NET Core روی localhost اجرا شدند. آخرین اجرای `tests/Smoke` با exit code صفر تمام شد.

## بررسی‌های موفق

- MVP فضای ارائه واحد: تست دو مرورگر با exit code صفر؛ شروع اشتراک مدرس، ورود فراگیر حین اشتراک، بازگشت به تخته با حفظ رسم و پایان capture مرورگر همگی موفق شدند. پنجره انتخاب سیستم‌عامل با Canvas capture جایگزین شده، اما ویدئو واقعاً از LiveKit عبور کرده است.
- حذف تب‌های انتخاب محتوا برای فراگیر و حفظ چیدمان موبایل بدون overflow.
- سلامت بک‌اند و LiveKit از `/api/health`.
- رد کد نادرست مدرس با 403.
- جلوگیری از نوشتن فراگیر روی تخته در خود API با 403.
- ذخیره تخته حتی قبل از ایجاد اتاق رسانه؛ اعلان ناموفق، ذخیره موفق را از بین نمی‌برد.
- رد revision قدیمی با 409 و جلوگیری از overwrite.
- دریافت Snapshot برای عضو جلسه و رد دریافت بدون نشست با 401.
- اتصال دو مرورگر واقعی Chrome headless به یک اتاق LiveKit.
- تحویل چت Reliable Data بین دو مرورگر.
- دریافت فریم ویدئو و track صوتی در مرورگر فراگیر با دوربین و میکروفون مصنوعی.
- نمایش پیش‌نمایش دوربین محلی مدرس.
- رسم با ورودی pointer مرورگر و نمایش آن برای فراگیر، با polling فراگیر خاموش؛ اعلان تخته واقعاً از LiveKit Data دریافت شد.
- بازیابی تخته بعد از refresh و ورود مجدد فراگیر.
- بازیابی فایل تخته متعلق به اجرای قبلی پس از توقف و راه‌اندازی مجدد بک‌اند؛ این مورد جداگانه با HTTP هم بررسی شد.
- نبود overflow افقی در عرض 390px.
- بازبینی بصری تصویر ورود، محیط کلاس و اندازه موبایل.
- اجرای مجدد start روی سرورهای روشن، بدون ایجاد پردازش تکراری، لینک دمو را برمی‌گرداند.

## بررسی دستی پیش از دمو

دستگاه‌های تست مصنوعی بودند؛ شنیدن واقعی صدا و استفاده از میکروفون/دوربین فیزیکی تأیید نشده‌اند. Screen Sharing پیاده‌سازی شده، ولی بازشدن picker سیستم‌عامل و نمایش پنجره واقعی به انتخاب کاربر نیاز دارد و در تست خودکار بررسی نشده است.

تست ظرفیت، آزمون امنیت Production، ضبط Egress و تضمین نگهداری در خرابی دیسک/قطع برق جزو این PoC نیستند. برنامه برای دمو روی همین دستگاه طراحی شده است.
