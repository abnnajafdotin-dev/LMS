# پلن نهایی PoC سریع LiveKit

این پلن با درخواست جدید برای یک پروژه موقت با بودجه زمانی حدود ۱ تا ۲ ساعت جایگزین تحلیل قبلی شد. هدف، دمو و آزمایش LiveKit روی همین کامپیوتر است؛ پروژه بعداً حذف می‌شود. توسعه در این مرحله مجاز است.

## انتخاب حداقلی

- بک‌اند: یک ASP.NET Core Minimal API روی .NET 10، بدون پکیج NuGet اضافی.
- فرانت: HTML، CSS و JavaScript ساده؛ بدون React، Node، npm یا build جدا. فایل SDK LiveKit و فونت فارسی همراه برنامه سرو می‌شوند.
- LiveKit: سرور رسمی Windows نسخه 1.13.11 در حالت dev و فقط روی loopback؛ SDK مرورگر نسخه 2.17.2. نه Docker و نه سرویس ابری لازم است.
- تخته: Canvas ساده با قلم رنگی، ضخامت، حذف آخرین خط و پاک‌کردن؛ Excalidraw و SignalR از این PoC حذف شدند تا تمرکز روی LiveKit بماند.
- Snapshot: یک فایل JSON برای هر کلاس داخل App_Data؛ نه دیتابیس و نه Redis لازم است.
- رابط فارسی راست‌به‌چپ: صفحه ورود، تخته، ویدئوها، افراد، چت، وضعیت اتصال و نوار کنترل رسانه؛ قابل استفاده روی نمایشگر کوچک.

## قابلیت‌های دمو

۱. ورود با نام و شناسه کلاس، نقش مدرس یا فراگیر؛ مدرس با کد آزمایشی demo123.
۲. اتصال واقعی به اتاق LiveKit با token امضاشده در بک‌اند.
۳. فعال‌کردن اختیاری دوربین، میکروفون و اشتراک صفحه.
۴. دریافت رسانه کاربران دیگر، نمایش اعضا و وضعیت reconnect.
۵. چت با LiveKit Reliable Data؛ تاریخچه فقط در همان صفحه است.
۶. تخته اختصاصی مدرس، مشاهده فراگیر، ورود دیرهنگام و بازیابی با snapshot.
۷. لینک دعوت برای ورود پنجره دوم به همان اتاق.

## جریان تخته

مرورگر مدرس صحنه را با throttle حدود 250ms و حداکثر یک درخواست در حال اجرا به API می‌فرستد. سرور نشست آزمایشی، نقش، مدرس فعال، اندازه و revision را کنترل می‌کند. Snapshot ابتدا در فایل موقت نوشته و جایگزین فایل اصلی می‌شود. سپس backend با RoomService.SendData اعلان کوچک board.changed را از LiveKit منتشر می‌کند. مرورگر دریافت‌کننده snapshot مرجع را از API می‌خواند؛ بنابراین داده تخته از Screen Sharing مستقل است.

اعلان تخته تنها زمانی پذیرفته می‌شود که سرور آن را فرستاده باشد؛ پیام participant نمی‌تواند مرجع تغییر تخته باشد. هر سه ثانیه heartbeat/revision بررسی می‌شود تا اعلان ازدست‌رفته، ورود جدید یا reconnect با snapshot ترمیم شود. این روش برای PoC کوچک ساده است و برای 300 نفر بهینه‌سازی نشده است.

فراگیر اجازه نوشتن در endpoint تخته ندارد. مجوز data فراگیر برای چت باز است، ولی مجوز Whiteboard را API مستقل اعمال می‌کند. فقط یک مدرس با lease heartbeat سی‌ثانیه‌ای فعال است؛ اگر مدرس قبلی خارج شود یا lease منقضی شود، مدرس جدید می‌تواند وارد شود. این مکانیزم، نقش سازمانی و احراز هویت واقعی نیست.

## محدودیت‌های آگاهانه

- فقط دموی محلی؛ آدرس localhost برای کامپیوتر دیگر قابل استفاده نیست. اجرای شبکه‌ای نیازمند HTTPS/WSS، آدرس قابل دسترسی و تنظیم شبکه رسانه است.
- حساب واقعی LMS، SQLite، SignalR، Excalidraw، handover پیشرفته، فایل، حضور و غیاب و طراحی Production خارج از دامنه‌اند.
- ضبط/Egress پیاده‌سازی نمی‌شود؛ اضافه‌کردن آن پروژه و زیرساخت جدا می‌خواهد.
- تخته تا 300 خط، هر خط حداکثر 1000 نقطه و Snapshot حداکثر 128 KiB دارد. صحنه کامل منتقل می‌شود؛ مناسب تست کوچک، نه ادعای ظرفیت 900 کاربر.
- ACK بعد از نوشتن فایل صادر می‌شود؛ backup و تضمین قطع برق دیتابیس وجود ندارد. تغییر تأییدنشده ممکن است از دست برود.
- نشست‌های ورود در حافظه‌اند و پس از restart بک‌اند باید دوباره وارد شد؛ فایل تخته باقی می‌ماند. دسترسی نشست و token دمو یک ساعت اعتبار دارد.
- کد مدرس و کلیدهای LiveKit dev عمومی و مخصوص همین دمو هستند. این برنامه نباید روی اینترنت منتشر شود.
- چت تاریخچه سروری ندارد. بعد از reconnect پیام‌های زمان قطعی بازسازی نمی‌شوند.

## ترتیب اجرا

۱. دریافت SDK محلی دات‌نت، باینری رسمی LiveKit و SDK مرورگر، بدون نصب سراسری.
۲. ساخت یک API و رابط تک‌صفحه‌ای، ورود و صدور token.
۳. اتصال رسانه، افراد، اشتراک صفحه و چت Data.
۴. تخته ساده، Snapshot، مجوز مدرس و بازیابی.
۵. build و تست API و دو مرورگر با دستگاه رسانه مصنوعی؛ بازبینی ظاهر دسکتاپ و موبایل.
۶. راهنمای اجرای کوتاه و سناریوی دمو؛ تست دستی دوربین واقعی و انتخاب Screen Share قبل از ارائه.

## فایل‌های اصلی

- src/Lms.Poc/Program.cs: API، token، دسترسی، Snapshot و اعلان LiveKit.
- src/Lms.Poc/wwwroot/: رابط، سبک، منطق مرورگر و فایل‌های vendor.
- scripts/setup.ps1: دانلود نسخه‌های ثابت و build اولیه.
- scripts/start.ps1 و stop.ps1: اجرای/توقف دو سرور محلی.
- START-DEMO.cmd و STOP-DEMO.cmd: میان‌بر ویندوز.
- tests/Smoke/: بررسی API و تست واقعی دو مرورگر با رسانه مصنوعی، بدون وابستگی تست خارجی.
- README.md: شروع سریع و دستور دمو.

## معیار پذیرش

- دو مرورگر در یک اتاق یکدیگر را ببینند و پیام Data ردوبدل کنند.
- دریافت ویدئو و track صوتی واقعی از LiveKit با رسانه مصنوعی تأیید شود؛ شنیدن واقعی با سخت‌افزار دستی بررسی می‌شود.
- فراگیر نتواند با HTTP روی تخته بنویسد؛ revision قدیمی رد شود.
- رسم مدرس برای فراگیر ظاهر شود و با reload/rejoin بازیابی شود.
- ظاهر فارسی در اندازه دسکتاپ و موبایل بدون overflow بررسی شود.
- اشتراک صفحه و صدا/دوربین فیزیکی نیازمند تأیید دستی کاربر و مجوز مرورگر هستند.
