# برنامه اتصال تخته به Excalidraw

تاریخ: 2026-11-11 — وضعیت: فاز اول (build و صفحه آزمایشی مستقل) پیاده‌سازی شده؛ اتصال به کلاس و گام‌های ۲ تا ۷ هنوز اجرا نشده‌اند. راهنما: [تخته مستقل](../frontend/whiteboard/README.fa.md).

## ارزیابی

بله؛ معماری فعلی برای اتصال مناسب است. بک‌اند .NET مستقل از موتور رسم است و نشست، مجوز انحصاری مدرس، ذخیره فایل، revision، اعلان سروری `board.changed` و polling سه‌ثانیه‌ای از قبل وجود دارند. اتصال در حد متوسط است: جایگزینی یک script به‌تنهایی کافی نیست، اما بازنویسی کلاس یا LiveKit لازم ندارد.

فرانت فعلی HTML/JS بدون build است. پیشنهاد، افزودن یک جزیره React مخصوص تخته با `@excalidraw/excalidraw` و build محلی است. بقیه کلاس در JavaScript فعلی می‌ماند. بسته متن‌باز، همکاری شبکه‌ای آماده ندارد؛ همگام‌سازی را همین برنامه انجام می‌دهد.

## محدوده نسخه اول

- مدرس: قلم، شکل، فلش، متن، انتخاب، جابه‌جایی، حذف و undo/redo داخلی Excalidraw.
- فراگیر: مشاهده؛ نوشتن در API نیز ممنوع می‌ماند.
- ذخیره، ورود دیرهنگام، refresh، اتصال مجدد، اشتراک صفحه و ضبط کلاس حفظ می‌شوند.
- تصویر، فایل ضمیمه، embed، لینک خارجی قابل‌اجرا، کتابخانه خارجی، چند صفحه و نوشتن هم‌زمان چند نفر خارج از این مرحله‌اند. ورودی نامجاز در سرور هم رد می‌شود.
- پنل کلاس RTL می‌ماند؛ بوم مختصات LTR دارد. متن فارسی، فونت محلی و نمایش در ضبط باید عملاً بررسی شوند؛ وجود ترجمه فارسی در نسخه انتخابی فرض نشود.

## تصمیم‌های فنی

1. خروجی build و فونت‌ها و assetهای لازم از همان .NET ارائه شوند؛ CDN در زمان اجرا لازم نباشد. Node فقط برای setup/build افزوده شود و اجرای عادی همچنان با START-DEMO باشد. نسخه‌های سازگار React، Excalidraw و ابزار build در شروع اجرا بررسی و دقیقاً pin و lock شوند؛ در این برنامه نسخه حدسی ثبت نشده است.
2. مسیر `/api/board` حفظ شود ولی قرارداد به schemaVersion=2 تغییر کند؛ جزئیات در [قرارداد](EXCALIDRAW-CONTRACT.fa.md). این تغییر همراه فرانت و تست‌ها منتشر شود؛ کلاینت قدیمی پشتیبانی نمی‌شود و باید refresh کند.
3. ابتدا snapshot خوانده و سپس editor قابل ویرایش شود. `onChange` فقط تغییر محتوای پایدار را وارد صف کند؛ تغییر selection، hover، zoom یا اعمال snapshot دریافتی باعث ذخیره دوباره نشود.
4. هر لحظه یک PUT؛ تغییرات حین ذخیره در صف آخرین scene بمانند. زمان‌بندی اولیه 500ms همراه سقف انتظار 2s در رسم پیوسته است؛ هنگام خروج صف تخلیه شود. GET قدیمی هرگز scene جدیدتر را بازنویسی نکند.
5. LiveKit فقط revision را اعلان کند؛ scene از HTTP دریافت شود. polling و heartbeat فعلی حفظ شوند. این روش near-real-time برای دموی کوچک است؛ ادعای ظرفیت ۳۰۰ نفر یا همگامی هر حرکت قلم ندارد.
6. فراگیر scene را fit کند؛ viewport شخصی و ابزار انتخاب‌شده ذخیره مشترک نشوند. مخفی شدن زیر اشتراک صفحه تخته را unmount یا پاک نکند؛ هنگام بازگشت resize و fit انجام شود.
7. ضبط دیگر به canvas داخلی Excalidraw وابسته نباشد: با `exportToCanvas` یک frame مستقل cache شود. روی تغییر محتوا async به‌روزرسانی، فقط یک export هم‌زمان و آخرین درخواست حفظ شود. حلقه 15fps ضبط از cache بخواند. قبل شروع ضبط اولین frame آماده شود؛ frame قدیمی بعد از جدید جایگزین نشود. صفحه اشتراکی همچنان اولویت دارد.
8. داده قدیمی قبل تبدیل backup شود؛ strokes نرمال‌شده روی صفحه مرجع 1200×675 به freedraw تبدیل شوند. تبدیل باید با helperهای همان نسخه، شناسه و فیلدهای معتبر بسازد و فقط پس از اعتبارسنجی کامل اتمیک ذخیره کند. فایل خراب یا schema ناشناخته خودکار پاک نشود.

## پایان کار و بازگشت

فهرست پذیرش در [چک‌لیست اجرا](EXCALIDRAW-CHECKLIST.fa.md) ملاک تکمیل است. بازگشت نیازمند کد قبلی و بازیابی backup داده قدیمی با توقف سرور است؛ صرف تعویض UI روی داده v2 کافی نیست. داده‌های ساخته‌شده پس از migration در نسخه قدیمی قابل نمایش نیستند؛ قبل rollback از آن‌ها هم نسخه نگهداری شود.
